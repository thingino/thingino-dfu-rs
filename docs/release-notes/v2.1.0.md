thingino-dfu 2.1.0 takes `dfu-remote` to an ESP32-S3: the daemon library now runs on
ESP-IDF, with the camera on the chip's USB host port, which is what the thingino backpack
firmware (thingino/thingino-backpack) is built on. To fit a microcontroller, images stream
through the daemon rather than being held, and clients send the USB-boot loaders rather
than the daemon storing them. The wire format is unchanged: older daemons and older clients
keep working with the new ones.

## dfu-remote on an ESP32

- `tdfu-usb` has a new backend, `tdfu_usb::espidf`, on the ESP-IDF USB Host Library.
  - It keeps a device open between operations, because a new interface claim restarts
    the data toggles that the Ingenic bootrom keeps counting.
  - It defers closing a device behind a control transfer the device never answered,
    which the library cannot cancel.
  - It power-cycles the port when an enumeration is abandoned.
  - It keeps one DMA transfer buffer per opening instead of one per chunk.
  - Its host handle can be cloned to watch the port from another thread.
- It runs on the ESP32-S3, and also builds for the ESP32-S2 and the ESP32-P4's high-speed
  port, untested on those.
- CI lints it for the ESP32-S3 with a pinned toolchain, and `cargo deny` reviews that
  target's dependencies.

## Streaming

- The daemon can stream `WRITE`, `BOOTSTRAP` and `READ` payloads rather than hold them
  (`DaemonState::with_stream_above`), and can read an image twice rather than stage it in
  a file (`ReadStaging::TwoPass`), so no buffer grows with the image. An ESP32-S3 without
  PSRAM writes and verifies 16 MiB this way.
- Byte-count progress frames go out at most ten times a second.
- The CLI shows progress while it is still sending a `WRITE` or `BOOTSTRAP`. Before, those
  frames arrived in one burst at the end.

## Loaders from the client

- A new `INFO` command (0x0A) reports the daemon's version and whether it holds loaders.
  To a daemon without loaders, the CLI and the web flasher send their own pair with the
  bootstrap. A daemon older than `INFO` answers it as an unknown command, and the client
  carries on as before.
- After a bootstrap with the client's pair, the DFU gadget reports the SoC that `DISCOVER`
  detected on that device, rather than "unknown".

## CLI

- `--host` takes a port, and IPv6 in every form: `NAME[:PORT]`, `IPV4[:PORT]`, a bare IPv6
  address, and `[IPV6][:PORT]`. A port in `--host` that disagrees with `--port` is refused.
  The README's `--host camera-host:5050` example did not work before this release.

## Verified

- A T31X camera through the ESP32-S3 daemon over Wi-Fi, without PSRAM: listing with
  detection, bootstrap, 16 MiB reads, and 16 MiB writes with verify, repeatedly, from the
  CLI and from the web flasher's remote mode.
- Every `--host` form against that daemon, over IPv4 and IPv6.
- The full gate: 1303 tests, clippy for the host, the browser build and the ESP32-S3, and
  the page's tests.
