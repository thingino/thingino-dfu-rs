thingino-dfu 2.0.1 is a loader refresh. The tools are unchanged from 2.0.0; what is new
is the 34 USB-boot loaders every archive carries, rebuilt from the gtxaspec/u-boot
`usbboot` release.

## The fix

The T31X USB-boot loader now brings DDR up with a conservative clock and memory
configuration, taken from the Ingenic Cloner: CPU/L2 clock source select `0x6a` with
APLL `0x04805900`, DDR at 400 MHz, and the matching controller timings. It previously
ran the CPU at 1392 MHz with DDR at 600 MHz.

On some T31 boards that old clocking made the mask ROM's second-stage cache writeback
corrupt U-Boot as it landed in DRAM. Nothing ran once the ROM handed control over, and
the bootstrap hung with no console output at all. Booting the same board from SPI-NOR was
never affected, which is why this only ever appeared over USB. A Wyze Video Doorbell v1
(T31ZX) could not be USB-bootstrapped at all before this change.

Only the T31X USB-boot loader's configuration changed.

## Also in this release

- All 34 loader variants were rebuilt from a U-Boot tree that now sits on the upstream
  v2026.10-rc4 base. Each archive's `README.md` names the exact U-Boot commit its loaders
  were built from.
- Docs: both flash stages are named as `a108:c309`.

## Verified

- The clock and DDR configuration in this fix was validated on hardware. A T31ZX Wyze
  Video Doorbell v1 that previously could not USB-boot at all now bootstraps all the way
  to the DFU gadget, and a T31X unit was re-tested as a regression check.
- The loaders shipped here are the CI builds from that same U-Boot commit. Every SoC's
  loader was rebuilt on the new upstream base, so reports from the other families are
  welcome.
