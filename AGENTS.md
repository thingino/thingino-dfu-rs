# AGENTS.md: how to work on the thingino-dfu Rust tree

This file is the rulebook for anyone working on this repository, human or coding agent.
Read §1 before touching anything: it says what is not negotiable, and why. The code
carries the story, so a comment states the fact it rests on rather than pointing at
somewhere else that holds it, and a rule that matters is pinned by a test. For the
bootrom and detection, the register captures under
`crates/tdfu-core/tests/fixtures/results/` are the evidence.

## 1. Hard rules

Each one has already cost real time or real hardware.

1. **Never push, never create a tag, never create a release** without being asked to.
   Commit locally on a branch. No exceptions, including "just to trigger CI".
2. **Never commit a lab IP address, hostname, credential, or path under a home
   directory.** Lab configuration comes from environment variables or an untracked
   file. If you are unsure whether something is lab-specific, it is.
3. **Never upload or execute anything on a bootrom** other than the real stage-1/U-Boot
   pair through the bootstrap path. No probe stubs. Identification is three bootrom memory
   reads of the registers U-Boot's `soc -m` loads: nothing uploaded, nothing executed, the
   bootrom left pristine for the real SPL.
4. **Never read a bootrom register through its physical address** (`0x13xxxxxx`). Use the
   kseg1 alias (`0xB3xxxxxx`): the mask ROM sets up no TLB, so the physical form raises an
   exception it never returns from and the bootrom stays enumerated with a dead USB handler
   until the power is cycled. The crate has a static assertion; do not weaken it.
5. **No `unwrap`, `expect`, or `panic!` in library crates.** CI denies them. A flashing
   tool must not abort mid-write on a lazy unwrap.
6. **No `async_trait` crate. No Emscripten. No `libusb` C dependency.** `nusb` is the
   native backend, proven on hardware and needing no `unsafe`; the browser drives WebUSB.
7. **Do not invent interfaces.** The traits and the types the crates exchange are frozen.
   If one is wrong, say so with the change you propose rather than applying it
   unilaterally: something else is being built against the same interface.
8. **Report faithfully.** If a test fails, say so with the output. If you skipped a step,
   say that. "Done" means every item on the list passed.
9. **Functional completeness, stable output.** Every operation (list, bootstrap, write,
   verify, read, erase, reboot, diag), every flag, remote operation over the network, the
   web flasher and Android are all supported; nothing is dropped because it was
   inconvenient, and a missing capability is a **bug**. Output (log text, stderr, the
   daemon's stdout) is whatever is useful, kept stable and pinned by tests. What does not
   move is the wire protocol: its framing and command layouts are proven and frozen.

## 2. Repo conventions

- **Commits**: subject plus at most 2-3 lines of body. To the point. No co-author
  trailers, no signatures, no "Generated by" lines. Commit every working step; do not batch
  a day into one commit.
- **Branches**: one per change, short and descriptive. Never commit to `main`.
- **Files, not directories, when staging.** Never stage a whole directory.
- **Citations into reference source** (a U-Boot line, a driver line, a captured register)
  are evidence and stay. A pointer to a document somebody has to open to learn the rule
  does not: write the rule.
- **Edition 2024**, MSRV in `Cargo.toml`'s `rust-version` (CI checks it in its own job);
  `rust-toolchain.toml` pins the toolchain the build and the gate run with.
- **The gate.** All of this passes before anything is called done, and CI runs the same
  list: `cargo fmt --all --check`; `cargo clippy --locked --workspace --all-targets
  --all-features -- -D warnings`; `TDFU_REQUIRE_LOADERS=1 cargo test --locked --workspace
  --all-features`; `cargo check --manifest-path fuzz/Cargo.toml`; `cargo deny check`;
  `typos`; `cargo machete --skip-target-dir`; and that clippy again as
  `cargo clippy --locked -p tdfu-wasm --target wasm32-unknown-unknown --all-targets
  --all-features -- -D warnings`, because the host lint compiles the wasm-only files away
  and the browser crate's largest module and its Node tests are linted only on the target.
  A change to the page also runs `npm --prefix web test`; a change to the Android drop-in
  also builds `cargo build --locked --release --target aarch64-linux-android -p tdfu-jni`.
  A tag runs the whole gate before anything is built, so an ungated commit cannot ship.

### 2.1 The pre-push hook, enable it in every clone

`.githooks/pre-push` runs the CI checks locally (fmt, then clippy `-D warnings`, then
test, in CI's order) and, before any of that, refuses a push that puts **lab data in a
tracked file**: a private subnet address as a dotted quad, a lab host's name, or a path
under a home directory. The patterns live in the hook; a line of prose that has to quote
one carries a `leak-scan-ok` marker, honoured only in Markdown and only per line, so it
stays greppable and reviewable, which a filename exclusion list is not. This repository is
**public**: an address committed today is a leak today, and a scan that runs only when
someone remembers it is not a scan. `core.hooksPath` is local config and does **not**
travel with a clone, so every working copy must run `git config core.hooksPath .githooks`
once. `TDFU_SKIP_HOOK=1 git push` skips the hook deliberately, for a WIP branch you want CI to
chew on. Nothing else should.

## 3. Standards

Workspace `Cargo.toml` carries these; crates inherit with `[lints] workspace = true`.

```toml
[workspace.package]
edition = "2024"
rust-version = "1.88"                 # let-chains in tests; CI checks it
license = "GPL-2.0-or-later"

[workspace.lints.rust]
unsafe_op_in_unsafe_fn = "deny"
missing_debug_implementations = "warn"
rust_2018_idioms = { level = "warn", priority = -1 }   # a GROUP: needs the priority or clippy errors
missing_docs = "warn"              # "deny" on tdfu-core and tdfu-proto once they stabilise

[workspace.lints.clippy]
pedantic = { level = "warn", priority = -1 }
cargo = { level = "warn", priority = -1 }
unwrap_used = "deny"               # no crate opts back in; an exception needs a reason= on the spot
expect_used = "deny"
panic = "deny"
module_name_repetitions = "allow"  # the curated allow-list lives HERE, never inline
```

`clippy::cargo` requires `readme` on every package (they point at the root README). Lint
*configuration* that cannot live in the manifest is in `clippy.toml` (`doc-valid-idents`,
`allowed-duplicate-crates`); `deny.toml` carries the matching `skip` for `syn` (two
proc-macro-only majors). `#[allow(async_fn_in_trait)]` on the async traits is
deliberate: the futures have to stay `?Send`. `#[expect(clippy::unused_async, reason = …)]`
on a stub is the accepted way to leave a `todo!()` async body; it self-removes when the
body lands. Every public error enum is `#[non_exhaustive]`; builders and status-returning
fns are `#[must_use]`; boundaries take `impl AsRef<Path>` / `impl Into<String>` and return
owned.

`tdfu-core` and `tdfu-proto` carry `#![forbid(unsafe_code)]`. `unsafe` is permitted only
in `tdfu-jni` and at the FFI edge of a `tdfu-usb` backend, each block with a `// SAFETY:`
comment. **Panics must not cross the JNI or wasm boundary**: `catch_unwind` at the JNI
edge, and a panic hook plus a pending-promise registry at the wasm one, where the target
aborts rather than unwinds so there is nothing to catch.

## 4. Decisions already made for you (do not relitigate)

- **D1, `Send`.** Core is generic over `LocalUsbTransport`, with no `Send` bound. Binaries
  drive each device on a `tokio::task::LocalSet` (or a current-thread runtime). The daemon
  is single-client; it does not need multi-threaded spawning. Do not add `trait_variant`.
- **D2, loader freshness.** `firmware/dfu/` is **not vendored** and not pinned. A
  `build.rs`-free `xtask fetch-loaders` downloads the current USB-boot loaders from
  `gtxaspec/u-boot`'s `usbboot` release into
  `target/firmware/dfu/<variant>/{tpl.bin|spl.bin,uboot.bin}`, with the U-Boot commit they
  were built from written beside them in `.usbboot-source`. CI runs it on every build,
  binaries locate the tree there, every archive README names that commit, and a tree
  already fetched from the same commit is reused unless `--force` is given.
- **D3, the test doubles.** The scripted `MockTransport` replays a transfer list and
  asserts the order. `FakeGadget` models a device instead: the f_dfu state machine, the
  2 MiB buffer flush, entity sequence counters that survive a USB reset, token-gated erase
  and reboot, fault injection. A model is checked against `f_dfu.c`, never against what the
  host expects, because a broken double manufactures false confidence.
- **D4, T4x auto-pick.** T40 and T41 share one SoC ID and one grade-code space, and the
  same code means a different DDR setup on each product line, so only the four codes seen
  on silicon resolve: `0x8888` to `t40n`, `0x7777` to `t40xp`, `0x9999` to `t41lq`,
  `0xAAAA` to `t41nq`. Every other `sub2` in family `0x40` is `Detection::Ambiguous`, and
  names both candidates rather than picking one.
- **D5, address form.** Bootrom addresses are the `Kseg1` newtype in `tdfu-core`:
  `Kseg1::from_phys` masks the low 29 bits and sets the kseg1 bits, `Kseg1::new` refuses
  anything else, and compile-time assertions pin every register constant to bits 31:29 ==
  `0b101`. `bootrom::read_memory` takes a `Kseg1`, so no call site can hand it anything else.
- **D6, version.** One workspace version, and every frontend reports it from the same
  place (`tdfu_core::build`).

Nothing is pushed, tagged or released here without being asked.
